# P07_FG S2 patches

Software: StataNow 19.5 MP (batch, `StataMP-64.exe //e do <file>` from Git Bash), R 4.5.2 + tidyxl 1.0.x for the Excel chains.
Sources, copied verbatim into this folder: `CreatingKhoe.do` (26 Oct 2013, 67 lines), `Do.do`, `Inequality.do` (from `original/14 FG Missing People/`), `productivity.do` (8 Nov 2013, 173 lines, from `original/Fourie Slaves/`).
`run_CreatingKhoe.do`, `run_productivity.do` and `diag_D1_keep_district0.do` are generated by `build_runs.sh`; original lines are inserted unchanged by line range (`sed -n 'a,bp'`). Only the lines below are new. Logs: `logs/`.

## Environment patches

### E1. Header (`version`, data path, log)
```diff
+version 13
+clear all
+set more off
+do "../../tools/paths.do"
+log using "logs/run_CreatingKhoe.log", text replace
```
`version 13`: the do-files have no `version` statement and date from 2013 (PROTOCOL S2: 13 for 2012–15).

### E2. Data load (the do-files have no `use` line; their headers name the file)
```diff
+use "$DATA/P07_FG/original/14 FG Missing People/missingpeople.dta", clear        // CreatingKhoe.do, Do.do
+use "$DATA/P07_FG/original/14 FG Missing People/slaveproductivity.dta", clear    // productivity.do
```

### E3. Inline instead of `do` for CreatingKhoe.do
`CreatingKhoe.do` issues `preserve` (l.10) without `restore`; when called with `do`, Stata restores the data on exit, so the in-memory sample is lost. The 67 lines are therefore pasted into the run file rather than called. No line is changed.

### E4. Project-local ado path; estout from SSC (productivity.do only)
```diff
+sysdir set PLUS "`c(pwd)'/ado/plus"
+sysdir set PERSONAL "`c(pwd)'/ado/personal"
```
`install_ado.do` installed `estout` (estout.ado 3.33, esttab.ado 2.1.4, 13 Apr 2026; same version as in `env/stata_ado.txt`). `cd output` before the verbatim lines so that `esttab using` writes into `output/`.

### E5. `drop ly` before productivity.do
`slaveproductivity.dta` was saved after an earlier session and already holds `ly lwheat lwine lcattle`; all other 41 variables are identical to `missingpeople.dta`. Line 5 (`gen ly = log(output)`) fails with r(110) otherwise. `ly` is regenerated identically by line 5.
```diff
+drop ly
```

## Extraction lines (no analytic change)

### X1. Table 1 sums (appended after CreatingKhoe.do l.67, same in-memory sample)
```diff
+gen _csd = district<4
+tabstat cattlekhoe slaves slavemales, by(year) stat(sum n) format(%12.4f)
+tabstat cattlekhoe slaves slavemales if _csd==1, by(year) stat(sum n) format(%12.4f)
+tabstat cattlekhoe slaves slavemales if district==4, by(year) stat(sum n) format(%12.4f)
+tabstat cattlekhoe slaves slavemales, by(district) stat(sum n) format(%12.4f)
```
The do-file computes `cattlekhoe` but tabulates it only by slave count (l.41). Table 1 values in `Dataset.xlsx` ('Opgaafrol', 'Khoe pop'!D) are pasted numbers; X1 regenerates them.

## Diagnostic D1 (not part of the reproduction)
`diag_D1_keep_district0.do` = `run_CreatingKhoe.do` with l.8 `drop if district==0` disabled (log `logs/diag_D1_keep_district0.log`). It reproduces every number in `Dataset.xlsx` 'Slave productivity' and 'Opgaafrol' that the verbatim code misses: one district-0 household in 1773 (39 slaves, 30 male slaves, 2.67 mudden and 0.13 leaguers per slave, no Khoesan) raises Table 1 slaves 1773/Total by 39, Table 5 Total N to 1,096 (means 9.014965/5.099913/1.411774/0.8549648) and Table 6 >5-slave Total N to 432 (6.251585/4.970221/1.037393/0.7814859). District rows are unaffected because tabstat shows district 0 as its own row, which the published tables omit. The published tables were therefore produced by a version of the do-file without l.8 (or before it was added); `results_original.csv` reports the verbatim code.
